## Правила
- Файл ведёт аналитик. Разработчик дописывает только раздел «Разработка», статус и `[x]`. Тестировщик (пока его нет — Owner) — только «Проверка» и статус.
- Номера:
  - фича — `F001`, `F002`, …;
  - доработка уже сданной (`[x]`) фичи — `F001.01`, `F001.02`;
  - пока фича не сдана, уточнение вносится в её текст;
  - номера не переиспользуются и не перенумеровываются.
- `готова к разработке` — только когда заполнены цель, поведение, приёмка и границы. Если без ответа Owner исполнителю пришлось бы выбирать поведение самому — карточка остаётся `черновик`, вопросы уходят Owner одним списком.
- Статусы — см. `.claude/team/common.md`.
- Пункт «Готово, когда» с пометкой «⏳ после F00N» проверяется, когда готова F00N. Карточку можно сдать в «готова к проверке» без него: это не блокер. Исполнитель проверяет такой пункт в F00N и отмечает его в исходной карточке.
- Запуск в Docker (`docker compose`, `deploy.sh`) проверяет Owner: на машине разработчика Docker нет (Owner, 2026-11-04: «я сам проверю запуск»). Разработчик пишет в разделе «Разработка», какие Docker-пункты ждут проверки Owner.
- Автотесты — базовый минимум (Owner, 2026-11-04, ради экономии токенов): pytest только в F002.1 (один smoke-тест), F004, F007, F008. Остальные карточки проверяются вручную по «Готово, когда». #### Задача
**Контейнеры**

В корне репозитория — `docker-compose.yml` с тремя сервисами:

| Сервис | Что внутри | Порт наружу (предложение) |
|---|---|---|
| `frontend` | Сборка React и раздача статики; `/api/…` проксируется на `backend` (например, nginx) | 3000 |
| `backend` | FastAPI + LangChain + LangGraph (`backend/Dockerfile`) | 8000 |
| `phoenix` | Официальный образ Arize Phoenix с зафиксированной версией (не `latest`) | 6006 (UI) |

Требования:
- Ключ и настройки попадают в `backend` из `.env` (`env_file`). В образы и `docker-compose.yml` ключ не пишется.
- `backend` знает адрес Phoenix по имени сервиса через `PHOENIX_COLLECTOR_ENDPOINT`.
- Порядок старта: `phoenix` → `backend` → `frontend` (`depends_on`). Если `backend` поднялся раньше готовности Phoenix, он не падает.
- Порты наружу задаются в `.env` с этими значениями по умолчанию и перечислены в README.

**Frontend на этом этапе**
- Сервис `frontend` собирает минимальное React-приложение-заглушку: одна страница с названием сервиса и результатом `GET /api/health`. F003 добавляет на неё форму входа, F009 — основной экран.

**Папка `data/` и SQLite**
1. В корне репозитория — папка `data/` с `data/.gitkeep`. Остальное содержимое в `.gitignore` (F001).
2. `data/` монтируется bind-mount'ом: в `backend` — `data/`, в `phoenix` — `data/phoenix/` (рабочая папка Phoenix). Всё, что должно пережить перезапуск, лежит только там.
3. Backend хранит SQLite-файл по пути из `DATABASE_PATH`, по умолчанию `data/app.db`.
4. При старте backend сам создаёт файл БД и таблицы, если их нет. Существующие данные не трогает.
5. Таблица `sessions`: id (случайный токен), login, created_at, expires_at. Таблицы пользователей нет: логин и пароль задаются в `.env` (F003). Другие данные — только если появится карточка.
6. Доступ к БД — стандартный `sqlite3` или SQLAlchemy, на усмотрение разработчика (зависимости — решение Owner 2026-11-04).

```text
{

}
```
Правила для промпта. Промпт хранится отдельным файлом или константой, чтобы README мог на него сослаться.

3. 6. `search_queries`: из названия, типа, производителя и значений входа, без несуществующих модификаций.

### F008. Обработка ошибок LLM API
- Статус: готова к разработке
- Родитель: F005
- Приоритет: P1
- Источник: ТЗ п.5 «Код должен корректно обрабатывать ошибки API…»; ТЗ п.7 «Обработка неполных или некорректных данных»; Owner, 2026-11-04: «LLM должна быть OpenAI».
#### Задача
Ошибки OpenAI (исключения `openai.*`, которые пробрасывает LangChain) превращаются в понятный ответ с тем же телом `{"error":{"code","message","details"}}` (как в F004):

| Ситуация | HTTP | `code` | `message` (смысл) |
|---|---|---|---|
| Нет `OPENAI_API_KEY` | 503 | `llm_not_configured` | «Не задан ключ API, см. README» |
| Провайдер вернул 401/403 | 502 | `llm_auth_error` | «Ключ API отклонён» |
| 429 / перегрузка | 503 | `llm_rate_limited` | «Лимит запросов, повторите позже» |
| Нет ответа дольше `LLM_TIMEOUT` | 504 | `llm_timeout` | «Модель не ответила за N с» |
| Сеть, 5xx провайдера, прочее | 502 | `llm_unavailable` | «Сервис LLM недоступен» |
| Ответ не по схеме после повтора (F007) | 502 | `llm_bad_response` | «Модель вернула некорректный ответ» |

Ошибка пишется в лог контейнера одной строкой: код, тип исключения. Ключ, промпт и вход в лог контейнера не попадают. Промпты и ответы видны только в Phoenix (F006). Там же трасса запроса помечается ошибкой.

Если Phoenix недоступен, генерация работает как обычно: ошибка отправки трасс не превращается в ошибку API.
#### Готово, когда

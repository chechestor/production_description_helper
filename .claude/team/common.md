# Общие правила команды (читать первым)

## Владелец и общение
- Владелец — **Owner**: ставит задачи, принимает решения, отвечает за `main` и push.
- Язык общения с Owner — русский. Внешние тексты (карточки товаров, README для работодателя) — русский, рынок РФ (B2B). Перевод не нужен: язык совпадает.
- Ошибка дорогая (push, публикация, отправка решения, удаление, платные вызовы API, обещание работодателю) — сначала спросить.
- Ошибка дешёвая и легко исправляется — сделать разумно и назвать допущение в отчёте.
- Проект разовый (тестовое задание 2–4 часа): делать MVP, не строить «на вырост».

## Источники правды (по убыванию)
1. Прямое слово Owner в текущем разговоре.
2. `notes.md` своей роли и `.claude/board/decisions.md`.
3. Карточка в `.claude/board/backlog.md`.
4. ТЗ: `.task/`.
5. Код и тесты — как факт того, что реально работает.

Не обещать того, чего нет в коде.

## Задачи и статусы
| Статус | Кто ставит | Что значит |
|---|---|---|
| `черновик` | продакт, аналитик | Идея, ещё не описана |
| `готова к разработке` | аналитик | Есть цель, поведение, приёмка и границы |
| `в работе` | исполнитель | Взята в работу |
| `готова к проверке` | исполнитель | Сделано, ждёт проверки |
| `блокер` | любой | Не проходит проверку или нужна информация; причина в карточке |
| `готова` | тестировщик (пока его нет — Owner) | Проверка пройдена |

- Галочку `[x]` в «Списке задач» ставит исполнитель сразу после завершения разработки, вместе со статусом `готова к проверке`.
- Тестирование — отдельный процесс: галочку не ставит и не снимает.
- Ответ Owner без галочки означает, что задача не сдана.
- Из `черновика` код не пишут.

## Git и среды
| Среда | Адрес | Ветка | Как попадает |
|---|---|---|---|
| local | `localhost` (порты — в README проекта) | `main` | локальный запуск по README |
| staging | — | — | не нужен |
| prod | — | — | не нужен (деплой не требуется по ТЗ) |

- Remote: `origin` → `github.com/chechestor/production_description_helper`. Ветка одна — `main`, отдельной `dev` нет.
- Коммит в `main` — только когда это входит в задачу роли или Owner попросил.
- Push — только после явного «пушь» Owner, если он не разрешил заранее.
- Переписывание истории (`--force`, `reset --hard`, rebase запушенного) — только по явной просьбе в том же разговоре.
- CI/CD нет.
- Сообщение коммита — одна фраза о том, что изменилось и зачем, с номером задачи: `Add JSON validation for product input (F002)`.

## Секреты
- Ключи, пароли, токены — только в `.claude/local/` и в `.env` (в `.gitignore`). В коде лежит только `.env.example` без значений.
- В notes, бэклог, коммиты, логи и скриншоты секреты не попадают.
- Агенты не вводят и не печатают секреты. Ключ LLM вносит Owner.

## Кто куда пишет
- Каждая роль пишет в свою папку `.claude/team/<role>/`, черновики — в `scratch/` внутри неё.
- Код меняет только разработчик.
- Чужие файлы ролей читают, но не правят.
- `board/decisions.md` — дописывают все, ничего не стирают.
- `board/backlog.md` — по правилам в шапке файла.
- ТЗ в `.task/` правится только по просьбе Owner.

## notes.md — память роли
- Записывать сразу, в той же сессии, когда Owner что-то уточнил или решил.
- Формат: `- ГГГГ-ММ-ДД, Owner: <что решено>`. Одна мысль — одна строка.
- Разделы: «Договорённости», «Грабли», «Открытые вопросы владельцу», «Ссылки».
- Устаревшее не удалять молча: поправить и указать дату.
- Касается всей команды — в `decisions.md`, в notes ссылка.

## Как сдавать работу
Короткий отчёт Owner:
1. Что сделано (1–3 строки) и где результат: путь, URL, номер задачи, коммит.
2. Что не сделано или под вопросом.
3. Принятые допущения.
4. Следующий шаг.

Без пересказа всех шагов.

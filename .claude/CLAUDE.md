# Production Description Helper — контекст

Тестовое задание (вакансия AI-разработчик), разовое, 2–4 часа. Прототип сервиса:
по JSON с данными о контрольно-измерительном приборе (название, производитель, характеристики, описание)
вызывает LLM и выдаёт черновик карточки товара для B2B-интернет-магазина: SEO-заголовок ≤70 симв.,
SEO-описание 800–1200 симв., ключевые характеристики, 3–5 поисковых запросов, commercial-блок для менеджера.
Главное требование — не выдумывать характеристики; нет данных → «данных нет».

## Где что
| Что | Где |
|---|---|
| ТЗ | `.task/Тестовое задание_ AI-разработчик.pdf`, `.task/task.md` (там же ссылка на YML-фид товаров) |
| Backend (Python, FastAPI) | `backend/` (создаст разработчик) |
| Frontend (React) | `frontend/` (создаст разработчик) |
| Примеры результата | `examples/` (создаст разработчик) |
| Инфраструктура | нет: только локальный запуск, без CI/CD и деплоя |
| Команда агентов | `.claude/` — см. `.claude/README.md` |

## Работа в роли
1. Прочитать `.claude/team/common.md`.
2. Прочитать `.claude/team/<role>/agent-instruction.md` и `.claude/team/<role>/notes.md`.
3. Уточнения Owner по своей работе — сразу в `notes.md` своей роли.

## Неснимаемые правила
- Одна ветка — `main`. Коммит — когда это входит в задачу роли или Owner попросил. Push — только после «пушь» Owner.
- Без явного «да» Owner в том же разговоре: push; удаление файлов и истории git (`reset --hard`, `push --force`, rebase опубликованного); публикация и отправка решения работодателю; письма и сообщения; платные вызовы LLM API; новые зависимости; любые действия вне папки репозитория.
- API-ключ — только в переменных окружения / `.env` в `.gitignore` или в `.claude/local/`. Никогда в коде, коммитах, notes, логах.
- Характеристики приборов не выдумывать — ни в коде-примерах, ни в промптах, ни в тестовых данных без источника.
